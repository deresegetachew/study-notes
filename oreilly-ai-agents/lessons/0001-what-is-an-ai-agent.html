An AI agent is a software system that uses an LLM as its reasoning engine, can call external tools, and loops until it completes a goal — rather than answering a single prompt. The shift from "call the LLM once" to "loop until done" is what makes something an agent.

Three things combine to make an agent: the LLM (the brain that decides), tools (the hands that act), and memory (the messages array that carries context between turns).

The 4-Step Agent Loop flowchart TD A["THINK — LLM reasons over messages array"] --> B{stop_reason?} B -->|end_turn| C["Return final answer to user ✓"] B -->|tool_use| D["ACT — execute the tool call"] D --> E["OBSERVE — append tool_result to messages"] E --> A

The messages array is the agent's state. The LLM is stateless — it sees only what you send each turn. Each loop iteration appends the assistant response and tool result, building up context.

''; } // tool_use — execute each tool call and loop messages.push({ role: 'assistant', content: response.content }); const results = response.content .filter(b => b.type === 'tool_use') .map(t => ({ type: 'tool_result' as const, tool_use_id: t.id, content: executeTool(t.name, t.input), })); messages.push({ role: 'user', content: results }); } }

An agent is a while loop around an LLM call. The loop exits when stop_reason === 'end_turn'. Everything else — tools, memory, multi-agent — is detail on top of that loop.

Classification or extraction with a fixed schema Any task involving user input When you need to call external APIs When building with NestJS Single calls are cheaper, faster, and more predictable. Use agents only when the task path cannot be known in advance. Which component decides which tool to call? The LLM The tool registry The messages array The stop_reason value The LLM reads the tool definitions in the request and decides — the developer only provides the implementations.
When would you choose a single LLM call over a full agent loop?

Single call when: response must be <2s, task is classification or extraction with a fixed schema, cost per query matters at scale, or auditability requires deterministic paths.

Agent loop when: task requires tool use, multi-step reasoning, or the path through the problem cannot be known in advance.

 How do you prevent an agent from looping infinitely on a buggy tool?

Set a maxTurns counter and return a graceful error string from the tool — do not throw. Throwing unhandled exceptions breaks the loop; returning "Error: ..." lets the LLM decide to give up or try something else.

Also: exponential back-off on transient failures, circuit-breaker pattern for persistent ones.

 What is the difference between prompt engineering and agent engineering?

Prompt engineering optimises a single LLM response. Agent engineering designs a system: what tools exist, how errors propagate, what gets stored in memory, how the loop terminates, how the agent behaves on unexpected inputs. The system prompt is one small input to a much larger design problem.

 Why does a growing messages array increase cost non-linearly?

Transformer attention is O(n²) in sequence length. Every turn of the agent loop appends more tokens — the 10th turn re-attends to turns 1–9. This is why trimming strategies (sliding window, summarisation) matter at production scale.

 Treating stop_reason as a boolean — always compare against the string constant, not truthiness. Appending tool results to a copy of the messages array instead of the original — silent state loss, agent loops forever. Writing tool descriptions that say what the tool does instead of when to call it — the LLM needs the latter to make routing decisions. Using throw inside tool implementations — unhandled exceptions abort the loop; return error strings instead.
